# 利用ガイド(radirec ingest)

らじれこで録音した M4A を、Jellyfin 音楽ライブラリ向けに整理・取り込みする CLI の使い方。

> 実装済み: **M1**(コア + CLI 取り込み)/ **M2**(Jellyfin 自動リフレッシュ)/ **M4-A**(radikool MP3 の
> 一括移行。移行用の `ingest --root` は ADR-0020 で CLI から削除済み)/ 統合設定の再適用(`radirec reapply`。§3・ADR-0016)。常駐・通知・制御・取込履歴・自己更新は **トレイ常駐 per-user モデル**(§6。ADR-0012/0013)。
> ソース跨ぎのアルバム統合(M4-C)/ 編集 GUI(M5)は未実装です。
>
> この §1–§5 は主に **dev/batch の CLI(`radirec.exe`)** の使い方。常駐運用は §6 を参照。

## 1. 前提

- **.NET 10 SDK**(実行のみなら .NET 10 ランタイム、または後述の自己完結 exe)。
- 実行ホストは **Windows** を想定(らじれこ出力ドライブと配信先 NAS の両方がネイティブに見えるため)。
- 配信先が NAS の場合は **UNC パス**(`\\host\share\...`)で指定します。Windows のドライブレター
  (`Z:` 等)は別プロセス/セッションから不可視になりうるため使いません(UNC が確実)。

## 2. セットアップ

設定は常に **`%LOCALAPPDATA%\RadirecData\`**(データルート)に置きます。CLI も常駐トレイもここを読み、
別の場所を指すオプションはありません([ADR-0020](adr/0020-cli-as-agent-front-via-control-channel.md))。
常駐トレイを一度起動すると、無いファイルは見本から作られます。手で置くなら、見本をそこへコピーして
自分の環境に合わせて編集します。

```
config/radirec.sample.json   → %LOCALAPPDATA%\RadirecData\radirec.json   (環境設定)
config/stations.sample.json  → %LOCALAPPDATA%\RadirecData\stations.json  (放送局マスタ)
config/programs.sample.json  → %LOCALAPPDATA%\RadirecData\programs.json  (番組 alias)
```

`radirec.json` の主な項目:

| キー | 意味 | 例 |
|------|------|----|
| `RadioRoot` | らじれこ出力ルート | `I:\\radio\\tmp` |
| `OutputRoot` | 配信先(ローカル or UNC) | `\\\\NAS\\share\\media\\radio` |
| `LedgerPath` | 取り込み台帳 DB(ローカルディスク) | `ledger.db`(相対) |
| `StabilitySeconds` | 書き込み中判定の待機秒数 | `15` |
| `SkipPatterns` | 除外するファイル名部分一致(ジャンク録音) | `["この時間はＮＨＫネットラジオでは"]` |
| `KnownRecordingKinds` | 剥がしてよい録音種別マーカー | `["TimeFree"]` |
| `Genre` | 既定ジャンル | `ラジオ` |
| `JellyfinUrl` | Jellyfin ルート URL(未設定なら更新しない) | `https://jellyfin.example.net` |
| `JellyfinApiKey` | Jellyfin API キー(ダッシュボード → API キー) | `xxxxxxxx…` |
| `ScanIntervalSeconds` | 常駐トレイの定期(安全網)スキャン間隔・秒 | `120` |
| `WatchDebounceSeconds` | 検知後スキャンまでのデバウンス秒 | `10` |
| `NotificationsEnabled` | **旧設定**。新規取込のトーストを出すかの**初期値としてだけ**読みます。切り替えは管理画面の設定ページで行い、値は `gui-settings.json` に持ちます(§6・[ADR-0019](adr/0019-gui-settings-file-for-ingest-toast.md))。取込失敗のトーストはこの値に関係なく出ます | `true` |
| `UpdatePrerelease` | アプリ内更新で prerelease(RC)も対象にするか(§6・ADR-0013) | `false` |
| `UpdateToken` | 更新フィード(GitHub Releases)読取用トークン。**private repo では必須** | `""` |

> 設定ファイルは JSON ですが、`//` コメントと末尾カンマを許容します。
>
> **パスの解決基準(ADR-0006)**: `LedgerPath` / `StationsFile` / `ProgramsFile`(および `RadioRoot` /
> `OutputRoot`)の**相対パスは `radirec.json` のあるディレクトリ基準**で解決されます。常駐トレイのデータルートは
> `%LOCALAPPDATA%\RadirecData\` で、これらが同居するため裸のファイル名(`ledger.db` 等)で足ります(ADR-0013)。
> 絶対パス(`C:\...`、UNC `\\host\share\...`)はそのまま使われます。

## 3. 実行

まず必ず **`--dry-run`** で、何がどこへ取り込まれるかを副作用なしに確認します。

```powershell
# 開発時(SDK から)
dotnet run --project src/Radirec.Cli -- ingest --dry-run

# 問題なければ実行(コピー + タグ付与)
dotnet run --project src/Radirec.Cli -- ingest
```

設定は常に **`%LOCALAPPDATA%\RadirecData\radirec.json`**(常駐トレイと同じデータルート。ADR-0006)を使います。
別の場所の設定を指すオプションはありません([ADR-0020](adr/0020-cli-as-agent-front-via-control-channel.md))。

> ⚠️ `--config` と `ingest --root` は ADR-0020 で削りました。付けて呼ぶと `Error: Unknown option 'config'.` の
> ように知らないオプションとして止まり、何もしません(既定の設定で黙って動くことはない)。付けて呼んでいた
> 既存のスクリプトがあれば外してください。

### 結果テーブルの見方

| 表示 | 意味 |
|------|------|
| 取込 | 実際に取り込んだ |
| 予定 | dry-run で取り込み予定 |
| 済 | 取り込み済み(冪等スキップ) |
| 未安定 | 書き込み中(まだ取り込まない) |
| ジャンク | スキップパターン一致で除外 |
| 対象外 | 当該 importer が扱えない |
| 失敗 | パース/コピー等に失敗 |

`(fallback)` は、放送局または番組名が alias 未登録で生名を採用したことを示します。

### Jellyfin ライブラリ更新

`JellyfinUrl` / `JellyfinApiKey` を設定しておくと、**取込が1件以上あった実行の最後に自動で
Jellyfin の全ライブラリスキャンを起動**します(`POST /Library/Refresh`。dry-run では起動しません)。
更新の失敗は取り込み成功を巻き戻さず、警告として表示します。

手動で更新だけ起動したいときは `refresh` コマンド(疎通確認にも便利):

```powershell
radirec refresh
```

### 統合設定を取り込み済みの回へ再適用する(`reapply`)

`programs.json`(`radirec.json` と同じフォルダ。既定は `%LOCALAPPDATA%\RadirecData\`)の正規名・統合は、新しく取り込む回にだけ効きます。あとから統合設定を足した(外した・
正規名を変えた)ときは、`reapply` で**取り込み済みの回を今の設定に揃えます**
([ADR-0016](adr/0016-reapply-program-settings-to-ingested-episodes.md))。ソースから取り込み直すのではなく、
出力済みのファイルを動かし、台帳の記録を書き換えます。

```powershell
# まず dry-run(どのアルバムの何回が動くかを副作用なしに確認)
radirec reapply --dry-run
# 問題なければ実行
radirec reapply
```

常駐からは、管理画面の **番組** ページ(§6)で番組の設定を編集すると、保存する前に同じ処理の dry-run で
変更前 → 変更後を確かめ、「保存して適用」で実行できます。

- **対象**は らじれこの回だけ。台帳の取込元フォルダ名を今の設定で解決し直し、記録されたアルバム名・パートと
  食い違う回を、**新しく取り込んだ場合と同じ形**(フォルダ・ファイル名・`album` / `title` / `track`)に揃えます。
  他のタグ(出演者など)は残します。radikool の回と、放送局が変わった回(`stations.json` の変更)は対象外です。
- 表示は**アルバム単位のまとめ**(変更前 → 変更後ごとの件数)と、1 回ずつの明細です:

  | 表示 | 意味 |
  |------|------|
  | 移動 / 移動予定 | ファイルを今の設定の場所へ移動・リネームし、タグと台帳を書き換える |
  | 台帳とタグ | ファイルは既に今の設定の場所にあるが、`album` / `title` / `track` が今の設定と違う(ファイル名だけ手で直した回)。ファイルは動かさずにこの 3 つのタグを書き換え、台帳を直す |
  | 台帳のみ | ファイルは既に今の設定の場所にあり、タグも揃っている(手作業で統合済み)。台帳だけを直す |
  | 重複 | 移動先に**同じ内容**のファイルが既にある。台帳をそちらへ向け、**元の場所のファイルは消さずに残す**(確かめて手で消す)。移動先のファイルの `album` / `title` / `track` が今の設定と違えば(手作業で統合先へコピーした回)、そのタグも書き換える(明細の詳細にその旨が出る) |
  | 対象外 | 移動先に**違う内容**のファイルがある・放送局が変わった・出力ファイルが無い・タグを読み取れない等。動かさない |
  | 失敗 | 実行中に失敗した。移動の回は、止まった段階により元のファイルか移動先のファイルのどちらかが残っている。タグを直す回(台帳とタグ・タグも直す重複の移動先)は、ファイルは同じ場所にあり、確定の前なら元のタグのまま、確定の後ならタグだけ揃っている。いずれも、もう一度 `reapply` すれば揃う |

- 移動は取り込みと同じく `.partial` に書いてから確定し、確定してから元を消し、最後に台帳を書き換えます。
  どこで止まっても元のファイルは壊れず、もう一度 `reapply` すれば揃います。空になった移動元フォルダは消します。
- 台帳とタグを直す回(タグも直す重複の回の移動先も)は、同じフォルダの `.partial` にコピーしてタグを書き、元の名前へ
  置き換えて確定してから台帳を書き換えます(確定までは元のファイルに触れません)。タグを読むのは、台帳を今の設定の
  場所のファイルへ向け直す回(台帳だけ直す候補・重複)だけです。タグを読み取れない回は対象外にします。
- 台帳の記録(放送局・アルバム名・パート)が今の設定と揃っている回は最初に飛ばすので、**その回のタグは確かめません**
  (全回のファイルを開くと NAS で重いため)。記録が揃っているのにタグだけ古い回は、手で直してください。
- まとめの件数は「移動・リネーム / 台帳とタグを直す / 台帳だけ直す / 重複が残っている / 対象外(/ 失敗)」の順に並びます。
- **2 回続けて実行すると、2 回目は何もしません**(揃っていれば「揃っています」と表示)。
- 台帳に取り込み済みのフォルダから、**統合設定の無い兄弟フォルダ**(同じ放送局で `(1)` / `(2)`、`Part1` / `Part2`、
  `8時9時` / `9時10時` のように、末尾の印を除くと同じ名前になるフォルダ)も一覧します。統合するか確かめる材料です
  (管理画面の番組ページの確認には出しません。1 回ずつの明細と一緒に `gui.log` には書きます)。計算は管理画面の
  ホームの**要対応**と同じで、`programs.json` の `KeepSeparate`(分けておく組)に記録した組は出しません(§5)。
- 移動か、タグを書き換える回(台帳とタグ・タグも直す重複)が 1 件以上あれば、最後に Jellyfin の通常のライブラリスキャンを起動します。書き換えた回の
  `album` / `title` / `track` が反映されないアルバムは、Jellyfin でそのアルバムのメタデータを更新してください
  (§5 の手作業手順の手順 5 と同じ)。

### radikool(旧 MP3 録音)の扱い

旧録音アプリ **radikool** の MP3 アーカイブ(`{局コード}/{番組名}_{YYYYMMDD}.mp3`)を監視ルートの外から
一度きり取り込む `ingest --root`(M4-A / #15)と、散在ソースを仕分ける `organize-source`(#81)は、
一回きりの移行のための機能なので [ADR-0020](adr/0020-cli-as-agent-front-via-control-channel.md) で削りました。
radikool の MP3 を取り込む処理(下の固有の扱い)は残っていて、`.m4a`/`.mp3` はファイルごとに自動で振り分けられます。

radikool 固有の扱い:

- **放送局は ID3 の `genre` タグが権威**(局コードフォルダは誤分類がありうるため信用しない。
  `genre` の表記ゆれは `stations.json` の alias で吸収)。番組名はファイル名 stem。時刻は持たない。
- **同日重複マーカー `(N)`**(例 `…_20200223(2).mp3`)は、中身の違う同日別録音として
  **両方**取り込み、`-N` / `track` / `title (N)` で区別します([ADR-0004](adr/0004-part-index-dedup-for-timeless-sources.md))。
- radikool 元タグ(`comment` の和文日付など)は案A で上書き/除去し、`artist`(出演者)は維持します。
- **番組名の表記ゆれ統合・らじれことのアルバム統合は M4-C(未実装)**。現状は radikool の番組名ごとに
  別アルバムとして入ります(例 `欅坂46`/`櫻坂46` は別アルバム)。局の正規化(配置)は今スライスで行います。

## 4. 取り込みの挙動

- **非破壊**: らじれこ原本(`RadioRoot`)は読むだけで変更しません。整理済みは `OutputRoot` にコピーされます。
- **配置**: `{放送局}/{番組}/{番組} YYYY-MM-DD.m4a`(Jellyfin はタグで束ねますが人間可読性のため)。
  統合番組(`programs.json` で複数フォルダを 1 番組に束ねたもの)の回は、`… YYYY-MM-DD-1.m4a` / `-2` と
  **パート**番号(由来フォルダの `Folders` 順・1 始まり)で区別されます。パート番号は放送日の重なりと関係なく付き、
  片方のフォルダしか録れていない日の回も `-1` などになります。
- **タグ(案A)**: `albumartist=放送局 / album=番組 / title=放送日 / disc=放送年 / track=MMDD /
  genre / comment=録音種別 / date=放送日(フル ISO)`。出演者は元タグを維持。
  統合番組の回は `title` に `(N)`、`track` に `MMDD*10+N`(N = パート番号)を付けてアルバム内の並び順を確定します。
- **冪等(import-once)**: アルバムのグルーピングは `(放送局, 番組, 放送日)` 単位ですが、**取り込みの
  重複判定は放送時刻も見ます**([ADR-0002](adr/0002-same-day-tiebreak-by-time.md))。同日でも時刻が
  異なる別放送(時間帯分割番組のパート等)は両方取り込まれ、同時刻の再取り込みだけがスキップされます。
  時刻を持たないソース(radikool)の同日重複は、ファイル名末尾の**重複マーカー** `(N)` で区別します
  (出力はパートと同じ `-N` / `(N)` / `MMDD*10+N` の形になります)
  ([ADR-0004](adr/0004-part-index-dedup-for-timeless-sources.md))。
  台帳(`LedgerPath`)に記録し、再実行しても重複しません。

## 5. アルバムの束ね方・表示名の整え方

**番組(アルバム)の同一性はフォルダ名で決まります**([ADR-0001](adr/0001-program-identity-anchored-to-folder.md))。
らじれこはファイル名の頭に週替わりゲスト名を入れますが、フォルダは番組ごとに安定しているため、
**同じフォルダの回は自動で 1 アルバムに集約**され、ゲストは各回の `artist` に残ります。例:
`オールナイトニッポン0(ZERO)` フォルダの全回は、ゲストが違っても 1 アルバムに束ねられます(**設定不要**)。

設定が要るのは次の 2 つだけです:

- **放送局の表記ゆれ**(`NHKラジオ第1(radiko)` → `NHKラジオ第1`、radikool の局コード等)を
  `stations.json` の別名で正規名へ寄せる。
- **表示名の整形 / 複数フォルダの統合**を `programs.json` で行う(任意)。

どちらも `radirec.json` と同じフォルダ(既定は `%LOCALAPPDATA%\RadirecData\`。§2)に置きます。

```jsonc
// stations.json
{ "Stations": [ { "Canonical": "ニッポン放送", "Aliases": ["LFR", "ニッポン放送"] } ] }
```
```jsonc
// programs.json
{
  "Programs": [
    // ラテン名の空白除去フォルダを綺麗な表示名に
    { "Match": { "Station": "J-WAVE", "Folders": ["LOGISTEEDRADIONOMICS"] },
      "Canonical": { "Album": "LOGISTEED RADIONOMICS" } },
    // 複数フォルダを 1 アルバムに統合
    { "Match": { "Station": "TBSラジオ", "Folders": ["パンサー向井のふらっと(1)", "パンサー向井のふらっと(2)"] },
      "Canonical": { "Album": "パンサー向井のふらっと" } }
  ]
}
```
`Match.Folders` は番組**フォルダ名**で照合します(表記ゆれは大文字化・空白除去で吸収)。
`Programs` に無いフォルダは、フォルダ名がそのままアルバム名になります(上の例はどれも任意の設定です)。
見本(`config/programs.sample.json`。初回起動時に `programs.json` として置かれるもの)は、この節の例と同じ種類の
エントリ(表示名の整形・複数フォルダの統合)をコメント無しで持っています。

**メモと、分けておく兄弟フォルダ**(任意。どちらも取り込み・再適用で動かす回は変えません):

```jsonc
// programs.json
{
  "Programs": [
    { "Match": { "Station": "TBSラジオ", "Folders": ["パンサー向井のふらっと(1)", "パンサー向井のふらっと(2)"] },
      "Canonical": { "Album": "パンサー向井のふらっと" },
      "Note": "1 回の放送が 2 つのフォルダに分かれて録音される" }
  ],
  "KeepSeparate": [
    { "Match": { "Station": "文化放送", "Folders": ["おとなりさん 8時台", "おとなりさん 11時12時"] },
      "Note": "時間帯で中身が違うので別の番組のままにする" }
  ]
}
```

- `Note`:エントリごとのメモ(なぜ統合したか等)。`//` コメントの代わりに持つ置き場です
  ([ADR-0017](adr/0017-management-window-owns-programs-json.md))。
- `KeepSeparate`:**分けておく兄弟フォルダ** — 兄弟フォルダ(§6)の組のうち、統合せず別々の番組として扱うと決めたもの。
  1 件は局とフォルダの組(`Match`。`Programs` と同じ形)と `Note`。ここに記録した組は、管理画面のホームの要対応
  ([ADR-0018](adr/0018-attention-items-derived-from-state.md))と `radirec reapply` の「統合設定の無い兄弟フォルダ」に
  出なくなります。記録した後に組へ新しいフォルダが加わったら、要対応にもう一度出ます。ふつうは要対応の「分けておく」で
  書きます(§6)。
- **古い版では読めなくなります**:`Note` / `KeepSeparate` を知らない版(更新を戻したトレイ・古い CLI)は、
  知らない項目のある設定を拒みます。トレイは起動しても取り込みを始めず、状態が「取り込み停止中(取り込みの起動に
  失敗しました(gui.log 参照))」になります。動いているトレイで設定リロードをしても(管理画面の番組ページで保存した
  とき等)、新しい設定には切り替わらず、前の設定のまま動き続けます(理由は `gui.log` に出ます)。
  CLI(`radirec ingest` / `reapply`)は設定を読めずに終わります。古い版に戻すときは、`Note` と `KeepSeparate` を
  消してください(使っていなければ何もしなくて構いません)。

> `programs.json` の変更は新しく取り込む回にだけ効きます。取り込み済みの回へ効かせるには、変更後に
> **`radirec reapply`**(§3「統合設定を取り込み済みの回へ再適用する」)を実行します。

### 既に取り込み済みアルバムを手作業で統合する(再適用で扱えない回の予備の手順)

取り込み済みの回を統合するには、まず `radirec reapply` を使います(§3)。次の手順は、再適用で**対象外**になった回
(移動先に内容の違うファイルがある等)や、radikool の回を、人が個別に判断して手作業で束ねるときの予備です。

**前提となる Jellyfin の挙動(重要)**: Jellyfin(本ライブラリ構成)は**アルバムを「フォルダ単位」でグルーピング**します。
`album` タグの書換だけではアルバムは移動・統合されません(メタデータの FullRefresh でタグ値は更新されても
アルバム所属は変わらない)。**ファイルを統合先フォルダへ物理移動して初めて統合されます**(表示名は `album` タグ由来)。

| 操作 | 結果 |
| --- | --- |
| `album` タグ書換のみ + 通常スキャン | 統合されない |
| `album` タグ書換のみ + メタデータ FullRefresh | タグ値は更新されるがアルバム所属は不変 |
| **タグ書換 + 統合先フォルダへ移動 + 通常スキャン** | **統合される** |

手順(NAS 書込のため Windows で実施):

1. 統合先の `album` タグ値は**手打ちせず**、統合先フォルダの既存ファイルから読み取って使う
   (全角 `＆` や `D.C.` の有無など、表記が 1 文字でも違うと別アルバムになるため)。
2. 移動元の各ファイルの `album` タグを 1 の値へ書き換える(`TagLibSharp.dll` でその場編集。他タグは保持)。
   `title` / `track` とファイル名(手順 3)は、**新規取り込みされた回と同じ形**になるよう、統合先が
   **統合番組**(`programs.json` の 1 エントリの `Folders` に異なるフォルダが 2 つ以上ある番組)かどうかで決める:

   | 統合先 | ファイル名 | `title` | `track` |
   | --- | --- | --- | --- |
   | 統合番組(パート番号あり) | `{album} {YYYY-MM-DD}-{N}.{ext}` | `YYYY-MM-DD (N)` | `MMDD*10+N` |
   | それ以外(表記ゆれ・フォルダ名の変更など) | `{album} {YYYY-MM-DD}.{ext}` | `YYYY-MM-DD` | `MMDD` |

   - N は**パート**番号 = 移動元フォルダがその `Folders` の何番目か(1 始まり)。手順 2 と 3 で同じ N を使う。
   - パート番号は放送日の重なりと関係なく付ける。片方のフォルダしか録れていない日の回も `-1` / `(1)` にする
     (単体取込では `title=YYYY-MM-DD` / `track=MMDD` になっているので書き換えが要る)。
   - 統合先フォルダに、統合設定の**前に**取り込まれた `-N` なしの回が既にある場合は、それらも移動元と同じく
     パート番号付きに揃える(N はその回の由来フォルダの番号)。残すと `track` の `MMDD` と `MMDD*10+N` が
     同じアルバムに混ざり、並び順が崩れる。
   - **例外(重複マーカー由来の `-N`)**: radikool の `(N)` 付き録音は、統合番組でなくても `-N` / `(N)` /
     `MMDD*10+N` で取り込まれている。統合先が統合番組**でない**ときは、その N をファイル名・`title`・`track` に
     そのまま残す。統合先が統合番組で、移動元に重複マーカー由来の `-N` があるときは、パートと番号がぶつかるので
     手作業統合しない。そういう回が出たら、実物を見て個別に判断する(パートと重複マーカーを両方持てるモデルは、
     らじれこ MP3 の `(N)` を扱う [#86](https://github.com/t-seki/radirec-tool/issues/86) で検討したが、
     らじれこ側の取り込み対象が無くなったため not planned で閉じた。radikool のこのケースを直す予定は無い)。
3. 統合先フォルダへ移動し、ファイル名を手順 2 の表の形にリネームする。パート番号の無いケースでは、
   統合先に同じ放送日のファイルが無いことを事前に確認する。
4. 空になった移動元フォルダを削除する。
5. `radirec refresh`(または Jellyfin の通常ライブラリスキャン)を実行する。これで**アルバムの統合(所属)**は反映される。
   ただし**書き換えたタグ(`title`/`track`/`disc` 等)が各トラックに反映されない**場合は、統合先アルバムに対して
   **メタデータの FullRefresh**(`POST /Items/{albumId}/Refresh?metadataRefreshMode=FullRefresh&replaceAllMetadata=true`)を
   実行する。移動でファイルは Jellyfin から「新規」として拾われるが、既存メタデータが残ってタグ由来値(パート番号 `(N)` や
   `track` 等)が出ないことがあるため。

> **台帳は手で触らない**: 手作業の手順は台帳を書き換えません。import-once は `source_path` でも再取込をガードするため、
> 出力側フォルダを動かしても元ソースの再取込は起きません(台帳の `output_path` と、アルバム名・パートの記録は古いまま残ります)。
> 手作業で束ねた番組に対応する統合設定を `programs.json` に足したら、続けて **`radirec reapply`** を実行してください。
> ファイルが既に今の設定の場所にあり、タグも揃っている回は「台帳のみ」として、台帳の `identity_key`・アルバム名・パート・`output_path` が
> 揃います(統合設定だけを足して台帳を古いままにすると、`identity_key` がずれて、アーカイブの再スキャン時に重複取込を招くことがあります)。
> ファイル名だけを直してタグを直していない回は「台帳とタグ」として、`album` / `title` / `track` も揃います。

## 6. 常駐トレイ(自動取り込み)

`Radirec.Gui`(トレイ常駐)を起動すると、録音を検知して自動で取り込み + Jellyfin 更新まで行います。
**取り込みワーカーをトレイプロセスが内包**し、ユーザーセッションで動きます
([ADR-0012](adr/0012-retire-service-for-tray-resident-per-user.md)。旧 Windows サービスは退役)。
らじれこは録音後 ~30 秒で強制スリープするため、**取りこぼしゼロはスリープ復帰時のキャッチアップ +
import-once 冪等で担保**します([ADR-0003](adr/0003-catchup-over-sleep-race.md))。トリガは①録音検知
(FileSystemWatcher)②スリープ復帰 ③起動時 ④定期(安全網)⑤手動(トレイメニュー)。新規取込時は
トレイが **in-process でトースト表示**します。**新規取込のトーストは管理画面の設定ページで止められます**。
**取込失敗のトーストは、この設定に関係なく常に出ます**(#152)。統合設定の無い兄弟フォルダは、トーストではなく
管理画面のホームの**要対応**に出ます(下記。#155 より前は、初めて取り込んだときに新規取込のトーストの最後の 1 行で
知らせていました)。

### 管理画面(Radirec を開く)

トレイメニューの **Radirec を開く**(太字の既定の項目)か、トレイアイコンの**ダブルクリック**で開きます
(requirements §10.3・#151)。同時に開けるのは 1 つだけで、開いているときにもう一度選ぶと、その画面を前面に出します
(最小化していれば元の大きさに戻します)。**閉じてもトレイに常駐し、取り込みは続きます**。設定を読み込めずに
取り込みが止まっているときも開けます。左の一覧でページを切り替えます(ホーム / 取込履歴 / 番組 / 設定 / バージョン情報)。

- **ホーム**: 取り込みの状態と最終スキャン(トレイメニューと同じ文言)、**今すぐ再スキャン**、**要対応**、
  取込履歴の新しい方の 5 件。
  - 状態は開いている間 2 秒ごとに読み直します。取込履歴の 5 件は、スキャンが終わったときに読み直します。
  - **要対応**は、いま判断を待っている事柄の一覧です([ADR-0018](adr/0018-attention-items-derived-from-state.md))。
    出来事の記録ではなく、台帳とディスクの `programs.json` / `stations.json` から毎回計算し直すので、原因が解消すれば
    消えます(既読にして消す操作はありません)。計算し直すのは、管理画面を開いたとき・ホームへ切り替えたとき・
    スキャンが終わったとき・「分けておく」を押した後です。設定を読み込めていないときは出しません。
    いまは**統合設定の無い兄弟フォルダ**の組だけを出します(同じ放送局で、末尾の `(1)` / `(2)`、`Part1` / `Part2`、
    `8時9時` / `9時10時` などを除くと同じ名前になるフォルダ。§3 の `reapply` と同じ判定):
    - 1 組ずつ「放送局: フォルダ / フォルダ(設定なし)」の形で出します。組の一部がすでに統合番組に入っていれば
      「統合番組『X』に入っていないフォルダ『…』があります」、分けておく組に記録した組に新しいフォルダが加わったら
      「分けておく組に、新しいフォルダ『…』が加わりました」を添えます。
    - **統合する**: 下書きを入れた番組ページの編集フォームへ移ります(ファイルには書きません)。統合番組がまだ無い組は、
      組のフォルダをパートの順に並べ、末尾の印を除いたフォルダ名をアルバム名にした新しいエントリの下書きです。組の一部が
      すでに統合番組に入っていれば、その統合番組の編集で、入っていないフォルダを**末尾に**足します(並べ直さないので、
      すでに取り込んだ回のパート番号は変わりません)。アルバム名を確かめて「決定」→「確認」→「保存して適用」を押すと、
      取り込み済みの回が統合先へ揃います。
    - **分けておく**: その場で `programs.json` の `KeepSeparate` に組を書き(バックアップ `.bak-yyyyMMdd-HHmmss` を
      作ります)、要対応から消えます。取り込みの結果は変えないので、再適用も設定リロードもしません。分けておく組に
      フォルダが加わった組なら、記録した組を置き換えます(メモは残します)。番組ページに保存していない変更があるときは
      押せません(書くと、番組ページの変更が保存できなくなるため)。`programs.json` に `//` コメントがあるときは、その場では
      書かずに番組ページの「分けておく兄弟フォルダを追加」の下書きへ移ります(保存するとコメントが消えるので、
      番組ページの保存の確認を通すため)。
    - `radirec.json` の `ProgramsFile` が空(`programs.json` を使わない設定)のときは、統合も分けておくことも記録できない
      ので、兄弟フォルダを出しません。
  - 「今すぐ再スキャン」を押すと、次のスキャンが終わるまでボタンの横に「手動再スキャンを要求しました」と出ます
    (バルーンは出しません)。取り込みが止まっているときは押せず、その理由をボタンの横に出します。
    番組ページで「確認」を押してから保存と適用が終わるまでも押せません。
  - 「すべて表示」で取込履歴ページへ移ります。
- **取込履歴**: 台帳の全取込を新しい順で一覧表示(読み取り専用。番組/放送局/放送/取込日時/ファイル)。
  列の見出しで並べ替えられます。開いた時点の一覧で、**「更新」を押したときだけ読み直します**(見ている最中に行がずれないように)。
  出力先パスは長いため列にはファイル名だけを出し、フルパスは ToolTip とページ下部の詳細欄
  (出力先 / 取込元。選択してコピーできる)で見せます。行を**ダブルクリック**(または Enter)で
  出力先をエクスプローラーで開き、**右クリック**から取込元を開く / それぞれのパスをコピーもできます。
  結果は「更新」の横に 1 行で出ます。ファイルが既に無いとき(取込元を消した・移動した等)は、
  たどれる一番近い親フォルダを開いてその旨を表示します。台帳を読めなければ「読み込みに失敗しました」と出ます(理由は `gui.log`)。
  設定を読み込めていないときは、台帳の場所が分からないので一覧を出しません。
- **番組**(#154・[ADR-0017](adr/0017-management-window-owns-programs-json.md)): `programs.json` の中身を
  2 つの一覧で見せ、画面から編集します。
  - **アルバム名と統合**(`Programs`): 放送局 / フォルダ / アルバム名 / 種類(フォルダ 2 つ以上なら「統合番組」、
    1 つなら「アルバム名だけ」)/ メモ(`Note`)。
  - **分けておく兄弟フォルダ**(`KeepSeparate`): 放送局 / フォルダの組 / メモ。
  - 「追加」「編集」(行のダブルクリックでも)「削除」は**画面の中の変更として溜めるだけで、ファイルには書きません**
    (「保存していない変更があります(N 件)」と出ます。「変更を取り消す」で読み込んだときに戻せます)。
    編集フォームのフォルダ欄は 1 行に 1 フォルダで、上から順にパート番号 1, 2, … が付きます。追加した行は一覧の末尾に
    置きます(並べ替えはできません)。放送局・フォルダ・アルバム名が空のとき、同じ放送局の別の行と同じフォルダを
    入れたとき(取り込みと同じ照合で比べます)は決定できません。
  - **確認**: まだ保存していない設定のまま、再適用(§3)の dry-run を行い、設定の変更前 → 変更後(変えた行の JSON)と、
    取り込み済みの回をどう揃えるか(アルバム単位のまとめ。1 回ずつの明細は `gui.log`)を見せます。取り込み中なら
    その走査の完了を待ちます(少し待っても終わらないときは「再適用の内容を確かめています」と出ます)。取り込みが
    止まっているときは押せません。
  - 確認の画面で選びます(既定の Enter は「戻る」):
    - **保存して適用**: `programs.json` を保存し、**設定リロード → 再適用の実行**を続けて行って、結果の件数を出します
      ([ADR-0016](adr/0016-reapply-program-settings-to-ingested-episodes.md)。取り込みも保存した設定で動くように、
      リロードと再適用の間に取り込みの走査は挟みません)。
      - 設定リロードに失敗したら(設定が壊れている等)、再適用は行わず、「統合設定の再適用を中止しました」と理由を出します
        (取り込みは前の設定のまま動き続けます)。
      - 読み直した設定が確認のときと違う、または確認の後に取り込みが進んで予定が変わったときは、実行せず
        「もう一度「確認」を押してください」と出ます。
      - どちらのときも保存は済んでいます。原因を直してから、もう一度「確認」を押すと、変更が無くても確かめ直して
        「保存して適用」で実行できます(書き込みはせず、設定リロードから試し直します)。前のリロードの失敗は「確認」を
        止めません(確認は画面の中の設定で行うため)。`stations.json` がまだ読めなければ、「確認」でその理由が出ます。
    - **保存だけ**: 保存して設定リロードだけを行います(取り込み済みの回はそのまま)。
    - **戻る**: 何もせず一覧に戻ります(溜めた変更は残ります)。
  - **保存**は `programs.json` 全体を書き直します(ADR-0017)。書く前に同じフォルダへ
    `programs.json.bak-YYYYMMDD-HHmmss` を作ります(前のバックアップは上書きしません)。
    - 管理画面から初めて保存するとき、`programs.json` に `//` などのコメントがあれば「コメントが N 件消えます
      (.bak に残ります)」と一度だけ確かめます。これからのメモは各行の「メモ」欄に書きます。
    - 読み込んだ後に `programs.json` をエディタで直していたら、保存しません。「読み込み直す」で読み直してから
      やり直します(この画面での変更は消えます)。エディタで直した後は、番組ページを開き直すと読み直します
      (画面に保存していない変更があるときは読み直しません。保存したのに再適用を実行できなかったときは、ファイルが
      変わっていなければ読み直さず、「確認」からその再適用を続けられます)。
    - 番組ページで `programs.json` を読めないときは、その理由と「読み込み直す」を出します。
    - 書き込みに失敗したときは、`programs.json` は元のままです(理由を画面に出し、`gui.log` にも書きます)。
  - 設定を読み込めていないときは一覧を出しません。`radirec.json` の `ProgramsFile` を空にして `programs.json` を
    使わない設定のときは、その旨と使い方を出します。
- **設定**(#152): ページを開くたびに、ディスクにある今の中身を読み直して見せます。
  - **取り込みの知らせ**:「新規取込のトーストを出す」のチェックで、新規取込のトーストを出すかを切り替えます。
    切り替えはすぐ効き(設定リロードは要りません)、`radirec.json` と同じフォルダの **`gui-settings.json`** に保存します
    (`radirec.json` は書き換えません。[ADR-0019](adr/0019-gui-settings-file-for-ingest-toast.md))。取込失敗のトーストは、
    このチェックに関係なく出ます。`gui-settings.json` にまだ値が無いとき(このページができる前から使っていたとき)は、
    `radirec.json` の旧設定 `NotificationsEnabled` を初期値として引き継ぎ、以後は `gui-settings.json` の値だけを使います。
  - **設定ファイル**: `radirec.json` と `stations.json` の中身を**読み取り専用で**見せます(`JellyfinApiKey`・`UpdateToken` は
    「(設定済み・表示しません)」と伏せます)。直すときは **ファイルを開く** で Windows で `.json` に関連付けたアプリ(エディタ)で
    開き(関連付けが無ければ「このファイルを開く方法」が出ます)、保存してから、直したファイルの段の **再読み込み** を押します。
    **ファイルを保存しただけでは反映しません**。`radirec.json` の段の「再読み込み」は設定リロードです(確認のあと、取り込みを
    一時停止して作り直します)。`stations.json` の段の「再読み込み」は、設定リロードに続けて再適用を確かめます(下記)。
    - 開く場所は**今読み込んでいる設定**から求めます。`stations.json` は `radirec.json` の `StationsFile` で場所を変えていれば
      その場所(相対パスは `radirec.json` のフォルダ基準)で、変えたのを「再読み込み」で反映すると開く場所も変わります。
    - ファイルが無ければ、初回起動時と同じ見本から作ってから開きます。開けなかったときは、その段の中に知らせます(理由は `gui.log`)。
    - `StationsFile` を空(`""`)にして `stations.json` を使わない設定にしているときは、その旨を出して開けません。
    - `stations.json` を直したら、保存してから `stations.json` の段の **再読み込み** を押します(#164)。設定リロードをしてから、
      取り込み済みの回を今の設定(`programs.json` と `stations.json`)と比べます。
      - 揃える回があれば、番組ページの確認の画面に移り、変える回の件数とアルバムごとの変更前 → 変更後を出します。
        **適用** で再適用を実行し、**戻る** で設定ページに戻ります(何も変えません)。確認を見せた後に設定が変わっていれば、
        実行せずにやり直しを求めます。
      - 揃える回が無ければ、ページは移らずに、その段に「取り込み済みの回は今の設定と揃っています」と出します
        (設定リロードは済んでいます)。
      - 確かめられなかったときは、ページは移らずに、その段に「統合設定の再適用を中止しました: {理由}」と出します。
        直した `stations.json` / `programs.json` の JSON が壊れている等で**設定リロードに失敗した**ときは、設定は反映されず、
        取り込みは前の設定のまま動き続けます。設定リロードの後の確かめ(dry-run)だけが失敗したときは、設定は反映されています。
        どちらも、理由を見て直してから、もう一度「再読み込み」を押します。
      - 番組ページに保存していない変更があるときは押せません(確認の画面に替わると下書きが見えなくなるため。下書きは消しません)。
        番組ページで保存するか取り消してから押します。
      - 放送局が変わる回(`stations.json` の正規名を変えた等)は、再適用では**対象外**です(§3)。
    - 取り込みが止まっているときは「再読み込み」を押せません。
  - `programs.json` は番組ページで編集します(上記。#154)。
  - **設定を読めないとき**(`radirec.json` が無い・壊れている): 設定ページの代わりに、読めない理由(読み込みのエラーそのまま)と
    `radirec.json` の場所、**ファイルを開く** と **再読み込みして再起動** を出します。直して保存してから「再読み込みして再起動」を
    押します。`programs.json` / `stations.json` は場所が分からないので開けません。JSON のエディタは内蔵しません。
  - **取り込みを起動できないとき**(`radirec.json` は読めたが、`programs.json` / `stations.json` の JSON が壊れている等。
    状態が「取り込み停止中(取り込みの起動に失敗しました(設定ページ参照))」): 設定ページの先頭に、起動に失敗した理由
    (JSON が壊れているときは `programs.json を読めません(JSON が壊れています): …` のようにファイル名付き)と、
    **programs.json を開く** / **stations.json を開く** / **再読み込みして再起動** を出します。直して保存してから
    「再読み込みして再起動」を押します(#168)。ページの残りは普段どおり出ます。
- **バージョン情報**: 版と、アプリ内更新(下記「更新」)。**今すぐ更新を確認**の結果(最新版です / 更新があります /
  失敗)はバルーンではなくページの中に出ます。更新が保留中のときだけ **更新 vX を適用して再起動** が出て、確認してから
  適用します(トレイメニューにも同じ項目が出ます)。更新の項目を出せないときは、その理由を出します:
  開発版・portable(Velopack で入れていない版)では「この版は自己更新の対象外です(開発版・portable)」、
  Velopack で入れた版で設定を読み込めていないときは「設定を読めないため、更新を確認できません」(更新用のトークンは
  `radirec.json` にあるため)。
- 管理画面の中でエラーが起きたときは、管理画面だけを閉じてバルーンで知らせます(トレイと取り込みは止めません。理由は `gui.log`)。

### 制御・更新(トレイメニュー)

トレイアイコンの右クリックから(かつての `radirec status/rescan/reload`〔named pipe〕は in-process 化で
**メニューに統合**。ADR-0012 で pipe は退役):

- **Radirec を開く**: 管理画面を開きます(上記)。
- **今すぐ再スキャン**: 自動トリガを待たず今すぐ 1 回スキャン(受理まで。バルーンで知らせます)。
- 次の項目は、トレイから管理画面へ移りました:取込履歴(取込履歴ページ。#151)、設定リロードと設定ファイルを開く
  (設定ページ。#152)、統合設定の再適用(番組ページの「確認」→「保存して適用」。保存 → 設定リロード → 再適用の順に
  行います。#154)、今すぐ更新を確認(バージョン情報ページ。#157)。
  - 再適用の確認に出ていた「統合設定の無い兄弟フォルダ」と、その提案を `programs.json` に追記して開く流れ(#144)も
    トレイと一緒に退役しました。兄弟フォルダは管理画面のホームの要対応に出ます(#155。「統合する」「分けておく」)。
  - `programs.json` は番組ページで編集して保存するのが本来の使い方です(ADR-0017。エディタは設定が壊れて読めないときの
    逃げ道)。エディタで直した `programs.json` を取り込み済みの回へ効かせるには、設定ページの `stations.json` の段の
    **再読み込み**(#164。設定リロードの後、`programs.json` と `stations.json` の両方で確かめます)か、`radirec reapply`(§3)を使います。
- **状態 / 最終スキャン**: 稼働状態・監視ルート・最終スキャン時刻/件数。
- **更新 vX を適用して再起動**: 更新が保留中のときだけ出ます。アプリ内更新(下記)。更新の確認は管理画面の
  バージョン情報ページで行います(#157)。

### 導入(Velopack Setup.exe・非 admin)

[Releases](https://github.com/t-seki/radirec-tool/releases) の **`Radirec-win-Setup.exe`** を実行するだけ
(**管理者不要**。[ADR-0013](adr/0013-velopack-per-user-updates.md)):

- 実行体: `%LOCALAPPDATA%\Radirec\`(Velopack 管理・更新で差し替わる)
- データ: `%LOCALAPPDATA%\RadirecData\`(`radirec.json` / `ledger.db` / `stations.json` / `programs.json` / `gui.log` /
  `gui-settings.json`〔管理画面の設定。#152〕)

初回起動時に設定を sample から生成します。`%LOCALAPPDATA%\RadirecData\radirec.json` を編集
(`RadioRoot` / `OutputRoot` / Jellyfin / 更新用 `UpdateToken`。管理画面の設定ページの「ファイルを開く」からも開けます)。トレイはログオン自動起動に自己登録されます。
動作ログは `%LOCALAPPDATA%\RadirecData\gui.log`。

### 更新(アプリ内・Velopack)

管理画面のバージョン情報ページの「**今すぐ更新を確認**」→ 新版があれば「**更新 vX を適用して再起動**」
(保留中はトレイメニューにも同じ項目が出ます)。起動時・24h ごとに自動でも確認し、新版を初めて見つけたときだけ
バルーンで知らせます。適用は確認(既定はキャンセル)→ DL → ワーカーを graceful 停止 → 差し替え → 自動再起動。
**private repo のため**、更新フィード読取用の fine-grained PAT(contents:read)を `radirec.json` の `UpdateToken`
に設定します。RC(prerelease)を試すときは `"UpdatePrerelease": true`。

### アンインストール

設定 → アプリ →「Radirec」→ アンインストール、または `%LOCALAPPDATA%\Radirec\Update.exe --uninstall`。
ログオン自動起動も解除されます。データ(`%LOCALAPPDATA%\RadirecData`)は残ります(消すと import-once 履歴が
失われる)。不要なら手動削除。

> 旧 admin 配置(`%ProgramData%\radirec` + Windows サービス)からの移行は
> [移行 runbook](migration-to-velopack.md) を参照。

## 7. 開発時の実行

SDK から直接動かす場合(`radirec.exe` を publish せずに):

```powershell
dotnet run --project src/Radirec.Cli -- ingest --dry-run
```

設定は常に `%LOCALAPPDATA%\RadirecData\radirec.json` を使います(§3。別の場所を指すオプションは無い)。

単一 exe を手元で作るには `dotnet publish src/Radirec.Cli -c Release`(win-x64 自己完結)。配布(常駐トレイの
Setup.exe・更新フィード)は CI がタグ push で **`vpk`(Velopack)** により Release へ発行します(§6・ADR-0013)。

## 8. 旧環境からの移行

旧 admin 配置(`%ProgramData%\radirec` + Windows サービス)や、さらに古い `C:\radirec\` 同居レイアウトからの
移行は、いずれも **台帳(`ledger.db`)を無傷で新データルート `%LOCALAPPDATA%\RadirecData\` へ運ぶ**のが要点です
(運び損ねると全放送回が「未取込」判定になり NAS へ再コピーが爆発)。現行の手順は
[移行 runbook](migration-to-velopack.md) にまとめています。
