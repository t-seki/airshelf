# 差し替え放送は、ファイル名の番組名ごとの利用者の判断で扱い、判断が出るまで取り込まずに保留する

Status: accepted(2026-09-27 の grill。#12。[ADR-0001](0001-program-identity-anchored-to-folder.md) のフォルダ名を番組の拠り所にする決定に例外を足す。[ADR-0016](0016-reapply-program-settings-to-ingested-episodes.md) の再適用、[ADR-0017](0017-management-window-owns-programs-json.md) の programs.json の書き手、[ADR-0018](0018-attention-items-derived-from-state.md) の要対応(**「取込通知には新規取込と取込失敗だけが残る」を改める**)、[ADR-0020](0020-cli-as-agent-front-via-control-channel.md) の CLI と関連)

らじれこは予約(時間帯)単位で録音するため、予約した番組の枠で別の番組が放送されると、その回も予約した番組のフォルダに入る。
番組の同一性はフォルダ名で決める(ADR-0001)ので、こうした回は予約した番組のアルバムに誤って入る(**差し替え放送**。CONTEXT.md)。

2026-09-27 に実データ(らじれこ 6,046 件)を調べると、フォルダ名がファイル名に入っていない回は 2,761 件あり、原因は 4 つに分かれた。

- **表記ゆれ・改名・スポンサーの交代**(同じ番組):`パンサー向井の#ふらっと (2)`・`おかしば 11時～12時`・`D.C.GARAGE`・ねごとのスポンサー交代など、約 2,600 件
- **ローテーションゲスト**(正規の回):ANN0 の `IMP`、1 件
- **一時的な差し替え**:伸びしろラジオの枠の `鉄旅・音旅`・`野村萬斎のラジオで福袋`、チャリで30分の枠の `辛坊治郎 ズーム`、`日向坂46の「ひ」` の枠のプロ野球実況など、約 60 件
- **後継番組**:`ベルクpresents日向坂46の…` のフォルダに、番組の終了後の 2024-10 から `土屋圭市のくるまの話` が 103 件

「ファイル名にフォルダ名が入っていない」だけで決めると、表記ゆれの約 2,600 件を誤って拾う。一方で、どの原因でも、同じフォルダには
同じ**ファイル名の番組名**(CONTEXT.md)が繰り返し現れる(`#ふらっと (2)` が 934 回、`辛坊治郎 ズーム` が 4 回、`土屋圭市` が 103 回)。
判断の要る (フォルダ, ファイル名の番組名) の組は 82 組だった。

## 決定

- **検出**:らじれこの録音ファイルを取り込むとき、ファイル名の番組名と番組フォルダ名をどちらも照合キー(`TextNormalizer.ToMatchKey`)にして、次の順に見る。
  1. ファイル名の番組名がフォルダ名を含む → これまでどおり取り込む
  2. (局, フォルダ, ファイル名の番組名) の組に利用者の判断が登録されている → その判断に従う
  3. どちらでもない → **取り込まずに保留する**
- **判断は (局, フォルダ, ファイル名の番組名) の組ごとに、`programs.json` に 3 択で覚える**:「この番組の回」(フォルダのとおり取り込む)/「取り込まない」/
  「別の番組として取り込む」(アルバム名を利用者が決める。局はそのまま)。一度判断すれば、同じファイル名の番組名の回は以後その判断で扱う。
  台帳の取り込み済みの回から自動で学ぶことはしない(台帳には差し替え放送の回も入っているため)。
- **保留**:保留した録音ファイルは、台帳の DB の**保留のストア**に記録する(取込元のパス・局・フォルダ・ファイル名の番組名・記録した時刻)。
  取り込んだとき・「取り込まない」と判断されたとき・取込元から消えたとき(#172 の取込失敗と同じ条件)に消える。
- **知らせ方**:要対応に、(局, フォルダ, ファイル名の番組名) の組ごとに出す(保留した回と、取り込み済みの判断待ちの回の数を添える)。
  保留のストアに新しい行を足した走査では、**保留シグナル**(CONTEXT.md。取込要約シグナル・取込失敗シグナルとは別の 3 つ目)を出し、取込通知(トースト)を
  1 度だけ出す。同じ録音ファイルを次の走査で保留しても出さない。取込要約シグナルは新規取込が 1 件以上の走査でしか出ないので、保留だけの走査の知らせを
  載せられない。取込失敗シグナルには載せない(保留は失敗ではない)。**ADR-0018 の「取込通知には、新規取込と取込失敗だけが残る」を改める。**
- **CLI の走査の実行**(`radirec ingest` と `--dry-run`):保留した回を結果(`--json` を含む)に出す。保留は失敗ではないので、**終了コードは変えない**
  (保留だけなら 0。ADR-0020)。
- **「取り込まない」と判断した後、再適用するまで**:取り込み済みの回は、要対応の「番組の設定と食い違ったままの回」に「出力先から消す予定」として出す
  (今のアルバム → 設定のアルバム、の形では表せないため区分を分ける)。再適用すれば消える。
- **取り込み済みの回**:要対応の計算が、台帳の `source_path` からファイル名の番組名を出して、判断待ちの回を見つける(台帳と設定だけ。NAS に触れない)。
  判断は**再適用**で当て直す。「別の番組として取り込む」は統合の変更と同じ移動・リネーム・タグ・台帳の書き換え、「取り込まない」は**出力先のファイルと
  台帳の行を消す**(dry-run の確認に区分を分けて出し、明示して実行したときだけ行う)。取込元は消さないので、判断を「この番組の回」に戻せば
  次の走査で取り込み直される。
- **入力**:管理画面の要対応の各組に「この番組の回」「取り込まない」「別の番組…」を置く。押すと番組ページの下書きに積むだけで、ホームに留まる
  (82 組をまとめて片付けられるように。「統合する」のように番組ページへ移らない)。番組ページで保存して再適用する。番組ページには登録した判断の一覧を
  出し、見る・直す・消すができる。CLI には判断のコマンドを足さない。`radirec attention` に出し、エージェントは `programs.json` を直接編集して
  `reload` / `reapply` する(ADR-0020)。
- **対象はらじれこだけ**。radikool は番組名をファイル名から採り、2020 年で凍結したアーカイブなので対象外(ADR-0016 の再適用と同じ)。

## 検討した案

- **回ごとに判断を覚える**:`辛坊治郎 ズーム` や後継番組の `土屋圭市` が来るたびに保留になり、毎週同じ判断が要る。採らない。
- **判断が出るまで、いまどおりフォルダの番組に取り込んで要対応に出す**:誤検知でも正規の回が遅れないが、判断するまで Jellyfin に誤ったアルバムの回が並び、
  「取り込まない」の回を必ず出力先から消すことになる。取り込みが import-once でなくなる。採らない。
- **判断の片方だけ(取り込まないだけ、または別の番組だけ)**:同じフォルダの中でも、要らない回(プロ野球実況)と残したい回(`野村萬斎のラジオで福袋`)に
  分かれる。採らない。
- **取り込み済みの「取り込まない」回は消さずに一覧に出し、利用者が手で消す**:破壊的な操作は足さずに済むが、約 60 件を手で消す作業が残る。取込元が残るので
  自動で消しても元に戻せる。採らない。
- **保留を走査の結果としてメモリにだけ持つ**:トレイを再起動するまで要対応に出ず、CLI の `attention` からも見えない。採らない。

## 結果

- 番組の同一性はこれまでどおりフォルダ名で決まる。ファイル名の番組名は、差し替え放送の疑いを見つける手がかりと、判断の照合にだけ使う(ADR-0001 の例外)。
- 取り込みの結果が、番組フォルダだけでなくファイル名の番組名の判断にも依存するようになる。再適用の対象(「今の設定で解決し直して記録と食い違う回」)に、
  判断の変わった回が加わる。
- 要対応は 4 種になる(統合設定の無い兄弟フォルダ・解決していない取込失敗・番組の設定と食い違ったままの回・差し替え放送の疑い)。
- 導入した直後は、取り込み済みの 82 組が要対応に並ぶ。以後、ファイル名の番組名が新しく変わるたび(スポンサーの交代・改名・新しい差し替え)に 1 回ずつ判断が要る。
- 残る制限:ファイル名の番組名が回ごとに変わる差し替え放送(`…【ゲスト】羽生結弦 パート１` / `パート２`)は、1 回ずつ判断が要る。
