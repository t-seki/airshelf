# programs.json の書き手を管理画面にし、書くときはファイル全体を書き直す

Status: accepted(#5 の GUI 設計、2026-09-25。[ADR-0016](0016-reapply-program-settings-to-ingested-episodes.md) の再適用、#144 / #148 の追記と関連)

管理画面(requirements §10.3)で番組の設定を編集できるようにするにあたり、`programs.json` を誰がどう書くかを決める。
いまの `programs.json` は利用者がエディタで直すファイルで、`//` コメント付きの JSON(JSONC)として読まれている。
#148 の追記(`ProgramsFileAppender`)は、コメントと並びをバイト単位で残したまま、提案を配列の末尾に**挿入するだけ**に
とどめることで、このファイルに手を入れている。

## 決定

- **`programs.json` の主な書き手は管理画面にする**。エディタで直すのは、設定が壊れて読めないとき(縮退時)の逃げ道として残す。
- **管理画面は、書くときにファイル全体を書き直す**。コメントは残らない。書く前に `programs.json.bak-YYYYMMDD-HHmmss` を作る
  (#148 と同じ仕組み)。読み込んだときの中身と、書く直前の中身が違っていたら(その間にエディタで直された)、書かずに知らせる。
- **初めて管理画面から保存するとき、ファイルにコメントがあれば「コメントが N 件消えます(`.bak` に残ります)」と一度だけ確かめる**。
- **コメントに書いていたメモは、エントリごとの `Note` 欄に持つ**(管理画面の番組の一覧に見せる)。
- **分けておく兄弟フォルダ**(CONTEXT.md)も `programs.json` に持つ。`Programs` とは別の最上位の配列 `KeepSeparate` に、
  局・フォルダの組・`Note` を並べる。`Programs` は「フォルダ → アルバム名」の対応だけを表し、「統合しない」印を混ぜない。
- `programs.sample.json` のコメントにある説明は docs(usage)へ移す。
- #148 の追記(`ProgramsFileAppender`)は、管理画面の要対応から統合できるようになった段で役目を終える。退役させる時期は、その実装の issue で決める。

## 検討した案

- **変えたエントリの範囲だけをテキストとして差し替える**(#148 のやり方を広げる):エントリの外のコメントは残る。
  ただし、エントリの中のコメントや、消したエントリの上に書かれたコメントの扱いが曖昧になり、編集・削除・並べ替えまで
  テキストの操作で正しく行うのは壊れやすい。作る量にも見合わないので採らない。
- **全体を書き直すが、`Note` 欄は作らない**:コメントに残していた「なぜ統合したか」の置き場がなくなるので採らない。

## 結果

- 管理画面は `programs.json` を普通の JSON として読み書きでき、編集・削除・並べ替えを素直に実装できる。
- 利用者がエディタで直す運用からは、一度だけコメントを失う(`.bak` から拾える)。以後のメモは `Note` に書く。
- `ProgramMasterConfig` に `Note` と `KeepSeparate` が加わる。どちらも取り込みと再適用の解決には影響しない
  (`KeepSeparate` を読むのは要対応の計算だけ。[ADR-0018](0018-attention-items-derived-from-state.md))。
