# 要対応は、起きた出来事の記録ではなく、いまの状態から毎回導く

管理画面(requirements §10.3)のホームに、利用者の判断を待っている事柄 = **要対応**(CONTEXT.md)を並べる。
いまの兄弟フォルダの知らせには、見える場所が 3 つある。どれも「いま判断を待っているものの一覧」にはなっていない。

- **取込通知(トースト)**:その走査で初めて取り込んだフォルダについて 1 度だけ出る。本文は 1 行しかない
- **`gui.log`**:全件が残る。ただし流れていくログなので、判断を待っているかどうかは分からない
- **再適用の確認**(トレイ・`radirec reapply --dry-run`):台帳全体から毎回計算し直して、統合設定の無い兄弟フォルダを並べる
  (`ReapplyService` の `UnintegratedSiblings`)。ただし、再適用を始めないと見えない

## 決定

- **要対応は、台帳・取込失敗のストア・番組の設定から、管理画面が表示するたびに計算する**。出来事の記録
  (受信箱)としては持たず、既読にして消す操作も作らない。原因が解消すれば一覧から消える。
- 並べるのは次の 3 種:
  - **統合設定の無い兄弟フォルダの組**:台帳にある取り込み済みの回の局と取込元フォルダから兄弟フォルダを探し、
    `Programs` にも `KeepSeparate` にも入っていない組を出す。統合する・分けておく、で消える。
    `KeepSeparate` に記録した組に新しいフォルダが加わったら、組が変わったのでもう一度出す。
  - **解決していない取込失敗**:失敗のストアから出す。同じファイルの取り込みに成功すれば消える(今の `Clear` のとおり)。
  - **番組の設定と食い違ったままの取り込み済みの回**:管理画面で「保存だけ」を選んだ場合など。再適用すれば消える。
- 「分けておく」の判断は、台帳ではなく `programs.json` の `KeepSeparate` に持つ(番組の設定の一部として、管理画面の番組ページで
  見えて、元に戻せるようにするため)。
- 兄弟フォルダの知らせはトーストから外す(取込通知には、新規取込と取込失敗だけが残る)。

## 検討した案

- **知らせを台帳に記録し、利用者が既読にしたら消す**(受信箱の形):見逃しは防げるが、原因が解消しても既読にするまで
  残る。統合しても消えない、あるいは解消していないのに既読で消える、という食い違いが起きる。採らない。
- **「分けておく」を台帳の別テーブルに持つ**:設定ファイルに比べて、利用者から見えにくく、元に戻す場所もない。採らない。

## 結果

- 兄弟フォルダの計算は、再適用がすでに持っている `UnintegratedSiblings`(台帳と設定だけで計算し、NAS に触れない)を
  土台にし、`KeepSeparate` を見る条件を足す。
- ほかの 2 種については、要対応の計算に必要なものが今のままでは足りない。実装の issue で次を扱う:
  - 失敗のストアは**失敗の理由を持っていない**(パス+フィンガープリントだけ)。理由の列を足す。
  - 失敗のストアは、取込通知が無効(`NotificationsEnabled=false`)だと**使われない**。通知の有無から切り離す。
  - 食い違った回を探すのに再適用の dry-run を使うと、エントリごとに出力先のファイルを確かめるので NAS に触れる。
    表示のたびに走らせるには重いため、台帳と設定だけで比べる計算を別に用意する。
- 取込要約シグナルは、兄弟フォルダの知らせを運ぶ必要がなくなる(取り込みの走査が兄弟フォルダを検出するかどうかは、実装の issue で決める)。
