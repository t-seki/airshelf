# 統合設定の再適用は、取り込み済みの回を動かして台帳を書き換える明示操作にする

Status: accepted(#126。requirements §8「自動パイプラインは再正規化しない。一括再適用は明示操作として提供する」を具体化。[ADR-0003](0003-catchup-over-sleep-race.md)・[ADR-0014](0014-content-fingerprint-import-dedup.md)・[ADR-0015](0015-output-collision-same-audio-check.md) と関連)。**#141(2026-09-25)で「台帳だけを直す」回の扱いを変更 — 下の追記を参照**

> **追記(#141、2026-09-25。本文は決定当時の記録なので直さない)**:「ファイルが既に計算どおりの場所にあり、台帳だけが古い回」の扱いを次のように変えた。
>
> - **きっかけ**:#139(PR #140)のマージ前検証で、手作業で統合したときにファイル名だけを直してタグを直していない回が「台帳だけ直す」に分類され、`album` / `title` / `track` が古いまま残ることが分かった(Jellyfin では同じフォルダの中に `album` タグの違う回が混ざる)。
> - **新しい区分「台帳とタグを直す」を足す**。「台帳だけ直す」候補の回に限ってファイルの `album` / `title` / `track` を読み、新しく取り込んだ場合の値と違えばこの区分にする。揃っていれば従来どおり「台帳だけ直す」。タグを読み取れない回は対象外にする。
> - **手順**:同じフォルダに `.partial` としてコピー → `album` / `title` / `track` だけを書き換える(他のタグは残す)→ 元の名前へ上書きのリネームで置き換えて確定 → 台帳を書き換える。確定までは元のファイルに触れないので途中で止まっても元は壊れず、確定後・台帳の前に止まった回は、次の再適用で「台帳だけ直す」(タグは揃っている)として揃う。
> - **表示**:確認ダイアログと CLI のまとめは「移動・リネーム / 台帳とタグを直す / 台帳だけ直す / 重複が残っている / 対象外」の順に並べる(NAS 上のファイルに書き込む回が確認の段階で分かるように)。「揃っています」の判定と、確認と実行の予定の照合にもこの区分を含める。
> - **Jellyfin**:通常のライブラリスキャンとメタデータ更新の案内は、移動だけでなく「台帳とタグを直す」回があるときにも行う(タグを書き換えるため)。

番組の設定(`programs.json` の正規名・統合)は新しく取り込む回にだけ効く。あとから統合設定を足すと、取り込み済みの回は別アルバムのまま残り、`docs/usage.md` §5 の手作業(タグ書換 → 移動・リネーム → 空フォルダ削除 → refresh)で直すしかなかった。2026-09-23 に実際にこれが起き、スクリプトのバグで作業が止まった。

そこで、今の番組の設定を取り込み済みの回に当て直す**再適用**を、利用者が明示的に実行する操作として提供する。**ソースから取り込み直すのではなく、出力済みのファイルを動かし、台帳の記録を書き換える。**

## 決定

- **対象はらじれこの回だけ**。台帳の `source_path` のフォルダ名を今の設定で解決し直し、記録されたアルバム名・パートと食い違う回をすべて対象にする(統合の追加・解除、正規名の変更を同じ仕組みで扱う)。radikool は 2020 年で凍結したアーカイブで、番組名もファイル名由来のため対象外。放送局が変わった回(`stations.json` の変更)も対象外として提示するだけにする。
- **ファイルが既に計算どおりの場所にあり、台帳だけが古い回は、台帳だけを直す**(手作業で統合した回)。
- **1 回分の手順は取り込みと同じ「`.partial` に書いてから確定」**:移動先へ `.partial` としてコピー → `album` / `title` / `track` だけを書き換える(他のタグは残す)→ リネームで確定 → 元のファイルを消す → 台帳を書き換える(`program`・`part_index`・同一性キー・`output_path`)→ 空になった移動元フォルダを消す。どこで止まっても、元のファイルが先に壊れることはなく、次の再適用で揃う([ADR-0003](0003-catchup-over-sleep-race.md) の中断耐性と同じ考え方)。
- **移動先に既にファイルがあるとき**:音声部分が同じなら([ADR-0015](0015-output-collision-same-audio-check.md) の比較)台帳だけを向け直し、元の場所に残ったファイルは消さずに「重複が残っている」と提示する。違う内容なら、その回は動かさずに「衝突のため対象外」と提示し、他の回は進める。取り込みのように ` HHmm` 付きの別名で逃がすことはしない(再適用の目的は「新しく取り込んだ場合と同じ形に揃える」ことで、別名はその目的から外れる)。
- **実行前に必ず dry-run の結果を見せる**:アルバム単位のまとめ(移動・リネームする回数、台帳だけ直す回数、対象外の回数)を確認ダイアログで示し、1 回ずつの明細は `gui.log` に書く。CLI(`radirec reapply --dry-run`)でも同じ計算を表示する。
- **再適用の開始時に設定リロードも行う**。再適用だけが新しい設定を使い、取り込みが古い設定のままだと、再適用の後に取り込んだ回がまた分かれたアルバムに入るため。読み込みに失敗したら再適用は中止する。
- **Jellyfin は通常のライブラリスキャンだけを自動で行う**。移動した回のタグが反映されないアルバムは、利用者が Jellyfin でメタデータを更新する(完了時に案内する)。アルバムごとの FullRefresh の自動化はしない。
- 処理本体は Core に置き、トレイ(worker の直列ループ上。取り込みと同時には走らない)と CLI の両方から呼ぶ。

## 結果

- `programs.json` に統合設定を足してから再適用するだけで、取り込み済みの回がパート番号付きで統合先アルバムへ揃う。手作業の統合手順(`docs/usage.md` §5)は、再適用で扱えない回の予備になる。
- 台帳は取り込みパイプラインだけでなく再適用も書き換える。同一性キーが変わるため、再適用の後も取り込みの重複判定(同一性キー・`source_path`・内容の 3 関門)は台帳と一致したまま保たれる。
- 残る制限:移動先に違う内容のファイルがある回は、人が個別に判断する。
