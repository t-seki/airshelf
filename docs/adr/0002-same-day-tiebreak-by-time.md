# 同日・別時刻の複数放送は時刻で区別する(dedup に放送時刻を含める)

Status: accepted(M1 の設計判断 D2「同一性キーは日単位、同日衝突時のみ時刻で tie-break」の未実装部分を実装・具体化)

同一放送日に別時刻の放送が複数ある番組(実データの `パンサー向井のふらっと(1)/(2)`=同日の別時間帯パート、
`おかしば10時/11時/12時` 等)で、日単位の同一性キーだけで冪等判定すると 2 件目以降が「取込済み」として
静かに欠落していた。よって **台帳(dedup)に放送時刻を持たせ、同一 `(局,番組,放送日)` でも時刻が異なる
録音は別放送として両方取り込む**。アルバムのグルーピングキー(`IdentityKey` = 局・番組・日)は据え置き、
dedup だけ時刻で細分化する。

## Considered Options

- **(採用) dedup キー = (局, 番組, 日, 時刻)。時刻なしはワイルドカード** — 時刻が異なれば別放送として両方取込、
  同時刻の再ダウンロードは冪等スキップ。radikool のように時刻が無いソースは「時刻なし」を同日どの時刻とも
  一致するワイルドカードとして扱い、cross-source の同一回を重複排除できる(D2 が日単位を選んだ本来の目的を保つ)。
- 日単位のまま(現状) — 同日・別時刻が欠落する(不採用、データ欠落)。
- 常に時刻をキーに入れる(ワイルドカードなし) — 実装は単純だが、時刻の無い radikool と らじれこ の同一回が
  別扱いになり cross-source 重複排除が壊れる。

## Consequences

- **出力ファイル名のパート区別**: 複数フォルダを統合した番組の同日パートは、由来フォルダの順番から
  決まる**パート番号**で区別する(`… YYYY-MM-DD-1.ext` / `-2`)。フォルダ由来なので取込順に依存せず
  決定的。パート番号が無い想定外の同日衝突は時刻サフィックス(`… HHMM`)を保険に使う。いずれの場合も欠落しない。
- アルバム(`IdentityKey`)は日単位のまま。時間帯分割番組を 1 アルバムに統合しても各パートが別トラックとして残る。
- **台帳スキーマ変更(破壊的)**: `imports` の主キーが `identity_key` 単独 → `(identity_key, broadcast_time)`
  複合、`broadcast_time` 列を追加。ALTER では PK 変更できないため、**起動時に旧スキーマ(broadcast_time 列なし)を
  検知したら台帳を作り直す**(台帳は再スキャンで再生成できる冪等性キャッシュ)。
- **radikool(時刻なし)は M4 で本格対応**。dedup のワイルドカード(時刻なし = 同日どの時刻とも一致)は
  **粗い**: 時刻なしのレコードが 1 件でもあると、そのキーのどの時刻の照会も一致してしまう。単一放送の
  番組では問題ないが、多パート番組に時刻なしレコードが混じると誤ってスキップしうる。radikool importer
  実装時(M4)に精緻化する(別 issue)。
  → **[ADR-0004] で supersede 済み**(M4)。ワイルドカードは撤去し、dedup は
  `(identity_key, broadcast_time, part_index)` の厳密一致に統一。時刻なしソースの同日重複はファイル名
  `(N)` 由来の part_index で区別する(#11 解消)。
